## 光标与快速拖动证据

A/B 固定同一时点的 48 个源码/资源文件，只调整五个直接 SDK 组件版本，隔离 obj/bin/输出。两份自包含构建成功，native/providers 哈希一致；传递依赖也有变化，所以结论属于 **SDK 组件组**，不唯一归因到某个 DLL。

| SDK 组件组 | 已点击输入的本窗口编辑时段（北京时间） | 保存的探针记录 |
|---|---|---|
| 2.5 | 21:15:45–21:16:13 | 23 条均为 `arrow` |
| 1.8 | 21:16:43–21:19:43 | 163 条均为 `ibeam` |

探针每 100 ms 观察，状态变化或 1 秒心跳落盘；上述数字不是点击数或所有原始采样总数。上游有高度吻合的报告：[TextBox 指针回归 #11204](https://github.com/microsoft/microsoft-ui-xaml/issues/11204)、[2.x 与 1.8 对照 #11543](https://github.com/microsoft/microsoft-ui-xaml/issues/11543)。本机 A/B 与最终版交互共同支持此次依赖选择，不能扩展为所有 Windows 环境已验证。

快速拖动日志进一步确认：按下事件坐标折算屏幕位置为 `(1477,230)`，处理按下时系统指针已经到达 `(1575,277)`。旧代码两次读取系统当前位置会丢失位移；新代码正确保存事件起点，抬起/捕获释放后位置保持 `(1448,227)`。日志在 `ui-final/card-smoke-3.jsonl`，时间 21:42:53–21:42:54。

诊断仅在独立测试配置加 `--card-smoke` 时启用；为自动化定位窗口，该模式临时把卡片加入窗口切换列表。普通产品启动不启用探针。普通工具窗口样式下的任务切换行为没有作为本轮 UI 自动化结果宣称通过。

## 仍可提升的方向与未覆盖范围

1. **编辑中保存与错误反馈**：桌面正文主要在结束编辑、隐藏/归档及退出时提交；可增加编辑中的防抖保存，并明确区分保存中、已保存、失败待重试。清空全文后当前恢复原内容，建议给出更明确反馈，避免被理解为删除。
2. **Markdown 冲突引导**：主 JSON 与 Markdown 同步状态分别显示，提供冲突文件定位及恢复入口；继续保留用户手改文件。Markdown 是单向文本记录，完整格式在 JSON 中，不是双向编辑同步。
3. **API 长度契约**：界面已拒绝超长新建，但外部直接 `cards.add` 仍有既有 clip 行为；建议手动新增 API 显式拒绝，语音自动剪裁单独定义。
4. **环境与耐久性**：本轮主要为本机 150% 缩放。多显示器/混合 DPI、跨屏吸附、100%/200% 缩放、键盘和辅助技术完整操作、复杂中文输入法、剪贴板组合、长时间压力、多进程同目录、断电及不同文件系统仍未形成完整实测矩阵。
5. **依赖变更的外围回归**：本次覆盖卡片和相关设置窗口。语音识别、麦克风、服务连接及其他窗口未因 SDK 组件回退重新做端到端验收；真实跨版本自动更新安装也不属于本轮卡片专项验收。
