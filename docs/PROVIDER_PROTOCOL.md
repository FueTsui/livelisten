# 识别服务协议（第 1 版）

实时聆听通过这个协议使用任何实时语音识别服务。服务是一个本地程序：应用启动它，从标准输入写消息，从标准输出读消息。内置的豆包服务 `providers/doubao_live.py` 就是按这个协议实现的。

## 基本规则

- 每行一个 JSON 对象，UTF-8 编码，以 `\n` 结尾。建议只输出 ASCII（非 ASCII 字符用 `\u` 转义）。
- 标准输出只能写协议消息。日志和调试信息写到标准错误；应用只把标准错误的摘要写入日志。
- 每个字段名用小写加下划线。收到不认识的消息类型或字段时忽略，不要报错。
- 应用为听写和字幕各启动一个进程。新会话的 `start` 可能在上一个会话的 `end` 之前到达（停顿分段、字幕切段）。最简单的做法是按到达顺序逐个处理。服务也可以让新会话在旧会话收尾时就开始连接，但输出必须保持开始顺序：较早会话的全部消息（直到它的 `end`）都要先于较晚会话的任何消息，因为应用把新会话的文字视为上一段已经结束。内置的两个桥接最多同时运行 2 个会话，并按这一规则排队输出。
- 正常 `stop` 位于本会话已排队音频之后；`cancel` 会清除该会话尚未写入管道的音频。若仍有待发送消息，但连续 3 秒没有一次管道写入完成，应用将终止旧服务并进入现有失败恢复流程。服务应持续读取标准输入，耗时的网络处理放到工作线程。

## 应用发给服务

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `start` | `id`、`sample_rate`（16000）、`language`（如 `zh-CN`） | 开始一个识别会话 |
| `audio` | `id`、`data` | 一段音频：base64 编码的 PCM16 小端、16 kHz、单声道，通常每段 40 ms |
| `stop` | `id` | 音频发完了，请返回最后的结果并结束会话 |
| `cancel` | `id` | 放弃会话，不需要结果 |
| `prepare` | — | 提前建立连接（「预连接」开启时发送），以缩短首字延迟 |
| `shutdown` | — | 结束会话并退出进程 |

## 服务发给应用

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `hello` | `protocol`（1）、`name`、`capabilities` | 启动后立即发送，且只发一次 |
| `connected` | `id` | 会话已连上服务，可选 |
| `text` | `id`、`text`、`stable` | 会话到目前为止的完整文字。`stable` 是开头已经确定、不会再修改的字符数（按 Unicode 字符计） |
| `final` | `id`、`text` | 会话的最终文字 |
| `end` | `id`、`cancelled` | 会话结束。每个 `start` 都必须有一个 `end` |
| `error` | `id`（可选）、`code`、`message` | 出错。带 `id` 时表示该会话失败，之后仍要发 `end` |

### 能力

`capabilities` 告诉应用这个服务能做什么，界面只提供对应的功能。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `interim` | 布尔 | 会返回临时结果（`text`） |
| `final` | 布尔 | 会返回最终结果（`final`） |
| `timestamps` | 布尔 | 会返回时间位置（预留；目前应用按收到文字的时间计时） |
| `languages` | 字符串数组 | 支持的语言，如 `["zh"]` |

应用忽略不认识的字段，例如旧版服务发来的 `speaker` 标签或 `speakers` 能力。

### 错误代码

| 代码 | 含义 |
| --- | --- |
| `connection` | 连不上识别服务或连接中断。听写会重连一次并补发音频 |
| `service` | 服务拒绝了请求 |
| `internal` | 服务程序自身出错 |
| `bad_message` | 收到的消息格式不对 |
| `module_missing` | 找不到识别模块（例如 `doubao_asr`） |
| `dependency_missing` | 缺少依赖库 |

应用自己还会报告 `spawn_failed`（无法启动程序）、`provider_exited`（程序意外退出）和 `timeout`（没有及时发送 `hello`）。

## 一次会话的例子

```
→ {"type":"start","id":7,"sample_rate":16000,"language":"zh-CN"}
→ {"type":"audio","id":7,"data":"AQD//w=="}
← {"type":"connected","id":7}
← {"type":"text","id":7,"text":"今天下午","stable":0}
→ {"type":"audio","id":7,"data":"..."}
← {"type":"text","id":7,"text":"今天下午三点开会，","stable":9}
→ {"type":"stop","id":7}
← {"type":"final","id":7,"text":"今天下午三点开会，请大家准时参加。"}
← {"type":"end","id":7,"cancelled":false}
```

## 添加自定义服务

在「设置 > 服务 > 自定义识别服务」中添加（参数用空格分隔），或在 `settings.json` 的 `services.customSpeech` 中填写：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一标识，只用英文字母、数字、`-` 或 `_`，不能是 `doubao` |
| `name` | 显示名称 |
| `command` | 程序的完整路径，或 `PATH` 中的程序名 |
| `args` | 参数数组 |
| `secretEnv` | 可选。接收密钥的环境变量名 |

需要密钥时，在设置窗口中保存。密钥存在 Windows 凭据管理器的 `LiveListen/speech.<id>` 下，应用启动该服务时只通过 `secretEnv` 指定的环境变量传入，不会出现在命令行参数或设置文件中。

保存后运行下面的命令检查服务能否启动以及它声明的能力：

```powershell
live-listen check --provider <id>
```
