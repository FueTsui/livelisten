# 架构说明：实时聆听

## 组成

```
LiveListen.exe（C# WinUI 3，界面外壳）
  └─ livelisten_native.dll（Rust，live-listen-ffi → live-listen-core）
       ├─ 音频采集：麦克风 / 电脑声音（WASAPI 回环）/ 混合 → 16 kHz 单声道 PCM16
       ├─ 全局输入钩子：快捷键、持续听写的结束键、写入时暂扣用户输入
       ├─ 焦点与目标：记录听写目标，识别密码框和管理员窗口
       ├─ 合成输入：SendInput 写入 Unicode 文字
       ├─ 随手记卡片：%APPDATA%\LiveListen\cards.json
       └─ 识别服务进程（每个音频通道一个，JSON 行协议，stdin/stdout）
            └─ python -B providers\doubao_live.py → doubao_asr → 豆包服务器
live-listen.exe（Rust CLI，调试与命令行识别，与界面共用核心）
```

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 核心 | `crates/live-listen-core` | 全部业务逻辑：设置、音频、听写规划、字幕分句、快捷键匹配、服务进程管理、密钥存取；`cards`（随手记卡片及其单独外观）、`engine/notes`（卡片的命令和事件） |
| C 接口 | `crates/live-listen-ffi` | `ll_start`、`ll_call`、`ll_free`、`ll_destroy`、`ll_version`；只做 JSON 转换 |
| CLI | `crates/live-listen-cli` | `devices`、`providers`、`check`、`listen`、`config` |
| 界面 | `app/LiveListen` | 浮条、字幕、设置窗口（含「随手记」页）、桌面卡片、托盘；不含业务规则 |
| 豆包桥接 | `providers/doubao_live.py` | 把协议消息转成 `doubao_asr` 的流式调用；不修改 `doubao_asr` |
| 安装程序 | `setup` | `setup.exe` 兼任安装与卸载程序（egui 界面）；`pack.exe` 把程序目录压缩后追加到安装程序后面。产品信息来自 `setup/install-manifest.json`；不链接核心，不读写设置内容 |

## 线程

| 线程 | 所在 | 作用 |
| --- | --- | --- |
| `engine` | 核心 | 唯一持有状态的线程；处理界面命令、音频帧、服务消息和钩子事件 |
| `audio` | 核心 | 在自己的线程里打开设备（结果以消息告诉 `engine`，引擎不等驱动），之后采集并重采样，每 40 ms 交给 `engine`；跟随默认设备的采集每 2 秒检查一次默认设备是否改变 |
| `input-hook` | 核心 | 低级键盘与鼠标钩子和它的消息循环；回调只做匹配并排队，合成输入在回调返回后发送。同一线程有一个只收原始键盘输入的隐藏窗口作看门狗：系统有按键而钩子连续 16 次没收到时，判定钩子已被 Windows 移除并重装（退避 30 秒、2 分钟、10 分钟）；切换到安全桌面（锁屏、Ctrl+Alt+Del、UAC）时清空按键状态并重装 |
| `provider-stdin` / `-stdout` / `-stderr` | 核心 | 每个服务进程三个；stderr 只用于日志摘要 |
| `provider-check` | 核心 | 一次性的识别服务检查 |
| 界面线程 | 界面 | XAML 与托盘；引擎事件经 `DispatcherQueue` 回到界面线程 |

## 数据流

### 快捷键设置

1. WinUI 按键录入框仅在前台聚焦时处理键盘事件。开始前通过 `hotkey.capture` 请求当前设置 HWND 的会话，等钩子线程确认后才显示可录入状态。
2. 捕获会话暂时停止业务快捷键匹配，按键继续送达前台控件；结束、失焦、换页和关闭均撤销会话。会话 token 隔离迟到的停止请求，结束后的保护持续到按键全部释放且经过 300 ms。
3. 控件在按键释放后提交候选值。先核对本地最新配置和核心冲突校验，再等待设置实际保存；失败保留草稿并提供重试，不提前显示成功。
4. `hotkeys.note` 默认按住 `Ctrl+Left` 开始，松开主键结束。单独用修饰键时仍有短暂等待，避免普通组合键误触发。`hotkeys.noteToggle` 调用托盘同款录音，`hotkeys.noteBlank` 创建桌面空白卡片。新增默认绑定发生冲突时保留已有绑定。

### 听写

1. 钩子识别快捷键，`engine` 记录当前前台窗口和焦点控件作为目标；若是密码框则拒绝，若是管理员窗口则提示。
2. 采集麦克风音频，发给听写通道的服务进程（开启「预连接」时进程和连接提前就绪）。
3. 服务返回文字。`dictation` 模块按写入方式计算要输入的内容：稳定写入只追加确认的文字；实时修正先写临时结果，再用退格原位修正。
4. `engine` 分步写入，每步最多一次退格、16 个普通字符或一个 Qt 字符。退格保留输入法兼容间隔；Qt 字符消息单次等待最多 15 ms。成功执行后才更新已写入状态。
5. 前台窗口变化时暂停写入；按住听写期间也监听鼠标。用户编辑、点击或暂存输入超时会立即改变输入版本，使旧的待写步骤失效，剩余文字可复制。
6. 结束时从最近一次文字更新起等待 3 秒，最长 12 秒。用户确实按键或点击后，暂存期限为 4 秒，单独的结束键也计入；超时先使后续注入失效，再重放输入。

### 字幕

1. 采集所选音源。声音超过阈值后开启识别会话（阈值取 −50 dBFS 与"最近 5 秒最低电平 + 6 dB"中较高的一个，但不超过 −40 dBFS，风扇等持续底噪不算说话），并补发前 320 ms 音频；会话满 8 秒后在文字停顿处收尾，最长 60 秒，静音时也会收尾。
2. `captions` 模块把文字分句，最近几行发给字幕浮层；文字不保存。

### 随手记

1. 语音随手记复用听写识别通道，不向其他窗口写字。按住模式收尾时不暂存键盘和鼠标输入；托盘和对应快捷键继续使用原来的持续模式。
2. 结束后，按开头的提示词归为待办或随手记，存入 `cards.json`，桌面显示新卡片。新建空白卡片不启动识别；`cards.add` 的可选字段 `editOnDesktop` 会显示桌面卡片，并用 `cards.changed` 的 `editCard` 指定需要打开编辑器的新卡片。
3. 卡片同时存储权威纯文本 `text` 与可选 `rtf`。富文本编辑成对提交，旧客户端仅修改纯文本时清除旧格式；元数据修改保留格式。RTF 有大小、结构与嵌入内容限制，界面加载时核对纯文本一致性。
4. `cards/markdown.rs` 将卡片投影为配置目录内“随手记/状态/YYYY-MM-DD.md”，使用 Windows 本地日期、生成标记与正文校验和。先原子写入新日期记录，再清理过时的程序生成文件；同名用户文件或手改记录不覆盖。Markdown 错误单独标记、定时重试，不将已持久化的 JSON 误报为未保存。

### 听写与字幕同时开启

- 字幕音源是麦克风时只做一次识别：听写占用麦克风期间，字幕直接显示听写的文字，听写结束后字幕恢复自己的会话。
- 字幕音源是电脑声音或混合时，两个通道各用一个服务进程，互不影响。

### 失败与恢复

- 听写中服务断开：内存中保留最多 90 秒音频，重连一次并补发；仍失败则停止并保留已识别的文字。
- 字幕服务启动失败：10 秒后再试；服务进程意外退出：5 秒后再试。
- 服务有待发送消息但 3 秒没有完成一次 stdin 写入：终止旧进程，按现有失败恢复路径重建。取消移除该会话尚未发送的音频；正常停止仍在本会话音频之后送达。
- 服务进程空闲超过设定时间（默认 5 分钟）后关闭，下次使用时再启动。
- 卡片保存失败：保留内存内容并每 5 秒重试。退出时再写一次；仍失败则写到 `%TEMP%\LiveListen-recovery` 的独立文件。正式文件与恢复副本都失败时取消退出，保留内存内容。
- 界面退出先提交卡片草稿并检查 `cards.list.unsaved`，保存设置，然后暂停接收调用并排空已接受的调用，通过 `shutdown` 请求核心确认保存。失败恢复调用和交互；成功后核心立即结束消息循环，再释放句柄，不重复保存。设置通过单个异步任务合并保存。
- `shutdown` 在后台等待明确结果，不套用普通命令的 20 秒超时，避免界面恢复后核心却迟到退出；操作系统文件写入与整个退出过程不承诺固定时限。
- 安装或升级：新文件先解压到安装目录内的 `.setup-<pid>\new` 并校验；请运行中的程序 `--quit` 退出后逐个替换，旧文件移到 `.setup-<pid>\old`。任一步失败就把每个文件移回原处并恢复注册信息，旧版本仍可启动（[ADR 0005](adr/0005-preconnect-levels-and-installer.md)）。

## 信任边界

| 输入 | 可信度 | 处理 |
| --- | --- | --- |
| 界面发来的 JSON 命令 | 同进程 | 核心校验命令名与参数；设置经 `sanitize` 修正范围和快捷键冲突 |
| `settings.json` | 本机用户可改 | 解析失败时使用默认值并报告问题；不含密钥 |
| 识别服务进程的输出 | 不可信 | 只接受协议内的消息，未知类型忽略；文字只作为输入内容，不作为命令执行 |
| `cards.json` | 本机用户可改 | 解析失败的卡片文件改名为 `.json.bad` 后从空白开始；卡片外观按设置的规则校验，无效颜色退回主题默认 |
| 用户添加的识别服务程序 | 用户自己负责 | 按用户填写的命令启动，只给它指定的环境变量中的密钥 |
